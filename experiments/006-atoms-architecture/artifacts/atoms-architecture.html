      02串联链路

      会话级队列只负责拉起进程，消息级队列逐条喂给它

      会话级 · Redis Stream
      mgx:chat:task[:lane]

      payload 为 user_id,chat_id,spawn_reason，只负责“拉起一个 Thinking 子进程”。group 为 mgx，每个主进程的 client_id 作为 consumer 竞争消费。

      消息级 · Redis Stream
      mgx:chat:event:{chat_id}:message

      每个 chat 一条 Stream，写入 message_id，由当前或新的子进程消费。

      已有存活子进程时 add_task 直接返回 False，不再发 chat_task；运行中再发的消息先排在消息级 Stream 里。

      1. 01主进程经 gRPC ListenChatTask 上报 READYbackend 以 client_id 为 consumer 执行 XREADGROUP，再 yield ChatTask{chat_id, config}
      2. 02fork 子进程，立即上行 CHAT_DONECHAT_DONE 的语义是“已 fork”，backend 据此 XACK chat_task 消息
      3. 03子进程另建 StreamChatCallback 控制流backend 下发 MESSAGE{id, type, content}
      4. 04同一 chat 串行：整轮结束才 MSG_ACKbackend 收到 MSG_ACK 后 XACK，才下发下一条
      10s
      主进程 HEARTBEAT 间隔
      60s
      子进程经 StreamChatCallback 心跳
      100
      进程数上限默认值，另按内存比例阶梯背压

      02串联链路

      流式靠 content_index 对账；断线不续传，由客户端重拉

      流式
      逐 chunk 推送

      首包 msg:create，之后每个 chunk 推 msg:update，带 content_index（累计字符数）。

      落库
      3s 增量

      空闲 update_interval 3.0s 时增量落库，流结束后全量覆盖写库。

      断线
      无服务端续传

      重连后重新 join_chat，HTTP 重拉消息列表；content_index 与本地长度不一致时 3 秒后重拉。

      停止
      HTTP PATCH，不走 socket

      status=STOPPING → INTERRUPT → 子进程 graceful_interrupt → 上行 STOP → 前端看到 STOPPED。

      thinking-gateway：新链路已接入，默认关闭

      开启后 backend 改发 mgx:chat:task:ingress:{gateway:<name>}，由外部 ThinkingGateway 消费并回调 /internal/thinking-gateway/prepare-chat-task。仓库样例 enabled: false；ListenChatTask 代码已标为 legacy，但仍是当前默认派发通道。实现仓库不在工作区。

      Socket.IO 参数
      • ping_interval: 25、ping_timeout: 20
      • 前端重连 10 次，delay 1–5s
      • join ack 3s 超时标为 failed

      03关键机制

      两本账：Agent 对话扣 oneapi credit，只有 AI Hub 扣 mgx-wallet

      Agent 对话
      oneapi credit
      • backend 下发 chat owner 的 oneapi default token，oneapi 走 Chat 分支
      • ConsumeCreditQuota：free（受每日限额）→ package → bonus
      • 订阅额度、兑换码、admin 补偿都写到这里
      AI Hub（发布应用调用 AI）
      mgx-wallet
      • token 名 app_{chat_id}，需 MGX_WALLET_SERVICE_ENABLED（代码默认 false，各环境取值未找到）
      • GetBalance 预检 → Decrease：先扣 bonus_ai 再扣 balance，allow_overdraft=true
      • SELECT … FOR UPDATE 锁账户行 + (biz_name, biz_no) 幂等，DUPLICATE_REQUEST 视为成功
      oneapi 结算：没有预扣
      1. 01
        锁内查余额
        可用额度 ≤ 0 返回 403
      2. 02
        写 Pending 交易
        credit_transaction 记录 preQuota，此时不扣余额
      3. 03
        按实际 usage 结算
        Chat 与 AI Hub 只在查余额和结算两处分流

      Quota = ceil(Σ token × 倍率 × ModelRatio × GroupRatio) · 1 quota = $0.002 / 1000 · QUOTA_PER_CREDIT = 100000（约 $0.2 / credit，推断）

      04服务间关系

      泳道沿 HTTP 主干连续，在 websocket 与 Thinking 出站处断开

      #跳机制状态
      01浏览器 → 入口前端代码不注入泳道头；推断来自浏览器插件或泳道 Host 网关外部注入
      02nuxt SSR → backend只对同源透传；选路 Map > Id > Host 规则 > 基线；带头时 Force=true，默认不回退带泳道
      03backend 入站 HTTPlane-routing SDK 全局 patch Starlette；出站 httpx / aiohttp 自动带头带泳道
      04浏览器 → Socket.IOSDK 只处理 scope.type == "http"，websocket 拿不到泳道上下文断开
      05backend → Redis Streamchat_task 改写为 <base>:<lane>；Map 非空时只认 atomsthinking 的映射改写 channel
      06Thinking → ListenChatTask泳道是部署级常量（MGX_CALLBACK_CLIENT_ID），只在这一路手工注入 x-lane-id部署级
      07Thinking 出站 gRPCStreamChatCallback、runtime、tool 都不带泳道 metadata断开
      08backend → FuncSea / mirror显式写入 X-Lane-Map带泳道

      结语

      一句话进入 backend，排队、执行、构建、发布，再落到两本账

      1. 进入
        HTTP
        nuxt-mgx → backend
      2. 排队
        Redis Stream
        会话级 + 消息级
      3. 执行
        gRPC
        Thinking + MetaGPT
      4. 构建
        MCP
        沙箱 mgx-tool
      5. 发布
        Kong
        静态 / Lambda
